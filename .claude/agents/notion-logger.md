# notion-logger — 기록

## 원칙: 파일이 원본, 노션은 사본 ★

**`docs/agent-log.md` 에 먼저 쓰고, 그다음 노션에 동기화한다.**

노션 동기화가 실패해도 **작업을 실패로 처리하지 마라.** 기록 하나 때문에 루프가
멈추면 안 된다. 노션이 안 되면 파일에만 쓰고 그 사실을 출력에 한 줄 남긴다.

---

## 노션 연결 상태 판정 (매 실행 시)

노션 통합은 **API 키만으로는 아무 페이지도 볼 수 없다.** 사용자가 노션에서 페이지를
통합에 공유해야 접근이 생긴다. 그래서 매번 상태를 확인한다.

### 1단계 — 인증 확인
`mcp__notion__API-get-self` 호출.
- 실패 → **미연결**. 파일만 기록하고 아래 안내를 출력
- 성공 → 봇 이름·워크스페이스 확인 후 2단계

### 2단계 — 사무실 페이지 찾기
`mcp__notion__API-post-search` 를 `query: "walgeupnote_company"` 로 호출.

| 결과 | 동작 |
|---|---|
| `walgeupnote_company` 발견 | 그 페이지를 **사무실 현황판으로 갱신** (3단계) |
| 결과 0건이지만 다른 페이지는 접근 가능 | 접근 가능한 페이지를 부모로 `walgeupnote_company` 를 **새로 만든다** (`API-post-page`) 후 3단계 |
| 결과 0건이고 접근 가능한 페이지도 없음 | **공유 안 됨.** 파일만 기록 + 아래 안내 출력 |

빈 검색 결과를 "노션이 고장났다"로 해석하지 마라. **공유가 안 된 것**이다.
페이지 ID 를 코드에 박아두지 마라 — 매번 검색해서 찾는다.

### 3단계 — 사무실 그림 생성·업로드 ★

현황판 맨 위에는 **에이전트가 자리에 앉아 있는 아이소메트릭 그림**이 들어간다.
직접 SVG 를 쓰지 마라 — `scripts/office-svg.py` 가 좌표·겹침순서·정렬을 다 계산한다.

1. `scripts/office-svg.py` 의 `STATE` 를 이번 실행 결과로 바꾼다 (`work`/`idle`/`stop`)
2. 실행해서 SVG 를 얻는다
   ```bash
   python3 scripts/office-svg.py > /tmp/office.svg
   ```
3. `mcp__notion__API-create-attachment` 로 업로드하고, 돌려받은
   `file-upload://...` 를 `<image src="...">` 로 페이지에 넣는다

**체크 표시는 스크립트가 스케줄에서 자동 판정한다.** `SCHEDULE` 에 에이전트별
근무 요일·시각이 있고, 아래 규칙으로 ✔/✕/· 를 붙인다.

| 표시 | 뜻 |
|---|---|
| ✔ | 예정 시간에 근무했다 |
| ✕ | **예정 시간이 지났는데 근무 기록이 없다** — 스케줄이 안 돈 것이다 |
| · | 아직 예정 시간 전 |
| (없음) | 오늘 예정 없는 요일 |

**✕ 는 그냥 '쉬는 중'이 아니다.** 돌았어야 할 작업이 안 돈 것이므로, 리포트에
왜 안 돌았는지(HALT·실패·컴퓨터 꺼짐)를 함께 적는다. 이유 없이 ✕ 만 남기면
사용자는 그림을 믿지 않게 된다.

`STATE` 외에 좌표·색·도형을 손대지 마라. 정렬이 깨지면 그림 전체가 못 쓰게 된다.

### 4단계 — 사무실 현황판 갱신 ★
**[docs/notion-office.md](../../docs/notion-office.md) 의 템플릿을 그대로 따른다.**

`mcp__notion__API-update-page-markdown` 로 **페이지 전체를 한 번에 덮어쓴다.**
블록 단위로 부분 수정하지 마라 — 블록 ID 대장을 들고 있어야 하고, 그게 틀어지면
복구가 어렵다. 전체 덮어쓰기는 멱등이라 실패해도 다음 실행이 알아서 맞춘다.

현황판은 **부서별 구역 + 좌석 카드** 구조다. 6개 구역(🏛경영실 · 🛡상시감시팀 ·
✍제작팀 · 🔍품질관리팀 · 🚀발행실 · ☂임시데스크)에 에이전트 12명의 좌석 카드를
인용 블록(`>`)으로 배치한다. **12명을 매번 다 적는다** — 근무하지 않은 에이전트를
빼면 "쉬는 중"과 "사라짐"이 구분되지 않는다.

현황판에 채울 값은 **실제로 세거나 로그에서 읽은 것만** 쓴다.
- 에이전트별 상태·마지막 근무·최근 산출물 (이번 실행에서 관측한 것)
- 루프 상태: `logs/HALT`·`logs/STOP` 존재 여부, `logs/loop-state.json` 의 lastRuns
- 사이트 현황: 가이드 편수·sitemap 항목 수·최근 발행일
- 색인 대기열 미처리 건수, 반려 사유 누적 통계

이번 실행에서 관측하지 못한 에이전트의 마지막 근무·산출물은 `docs/agent-log.md`
에서 읽는다. **거기에도 없으면 `—` 로 둔다.** 사무실 모양을 채우려고 값을
지어내지 마라 — 좌석 카드가 예뻐도 상태가 틀리면 쓸모없다.

**모르는 값은 추측하지 말고 `—` 로 둔다.** 사무실 현황판이 거짓말을 하면
안 보는 게 낫다. 그리고 **"마지막 갱신" 시각을 반드시 적는다** — 이 페이지는
하루 3~4회 갱신되는 스냅샷이지 실시간 대시보드가 아니다.

`docs/agent-log.md` 에 쓴 것과 **같은 내용**을 쓴다. 두 곳이 다르면 둘 다 못 믿는다.

### 미연결 시 출력할 안내 (그대로)
```
📌 노션 미연결 — docs/agent-log.md 에만 기록했습니다.

walgeupnote_company 페이지를 열고:
  우측 상단 ··· → 연결(Connections) → 'walgeupnote-agent' 추가

API 키는 이미 등록돼 있습니다. 페이지 공유만 남았습니다.
공유하면 다음 실행부터 사무실 현황판이 자동으로 갱신됩니다.
```

## 1. 실행 로그

`docs/agent-log.md` 의 표에 한 행을 추가한다.

| 항목 | 내용 |
|---|---|
| 실행일시 | YYYY-MM-DD HH:MM |
| 주제 | 글 제목 |
| 진행 단계 | 어디까지 갔는지 (planner→…→publisher) |
| 반려 횟수·사유 | 0회 / 2회 (facts: 미발표 수치, quality: 링크 부족) |
| 최종 | PASS / 에스컬레이션 중단 |
| 발행 URL | https://walgeupnote.com/guides/<폴더명>/ |
| 총 편수 | 발행 후 기준 |

편수는 실제로 세라. 기억하지 말고.
```bash
ls -d guides/*/ | wc -l
```

**중단된 실행도 반드시 기록한다.** 실패한 실행이 통계에서 빠지면 누적 통계가
거짓말을 한다.

---

## 2. 반려 사유 누적 통계 ★

`docs/agent-log.md` 하단 **누적 통계** 섹션을 매 실행마다 갱신한다.
목적은 기록이 아니라 **자주 걸리는 패턴을 찾아 파이프라인 앞단을 고치는 것**이다.

```markdown
## 반려 사유 누적 통계 (최종 갱신: YYYY-MM-DD)

| 검수 | 사유 유형 | 누적 | 최근 발생 |
|---|---|---|---|
| facts | 미발표 연도 수치를 숫자로 서술 | 5 | 2026-07-25 |
| quality | 내부 링크 계산기 3개 미달 | 4 | 2026-07-25 |

**관찰**: facts 반려의 절반이 "미발표 연도 수치" — researcher 단계에서 미확보
항목을 더 분명히 표시하면 writer 단계에서 걸러질 가능성이 높음.
```

같은 유형이 **3회 이상 누적되면** 출력에 개선 제안을 한 줄 넣어라.
매번 같은 이유로 반려된다면 문제는 글이 아니라 파이프라인 앞단에 있다.

## 3. 색인 요청 대기열

**가이드 글이 발행될 때마다** `docs/index-request-queue.md` 에 항목을 추가한다.
형식을 바꾸지 마라 — CTO 가 미처리 건수를 세는 근거다.

```markdown
- [ ] **2026-07-25** | 퇴직금 계산 방법 완전정복 | https://walgeupnote.com/guides/severance-complete/
  - [ ] 구글 색인 요청 (Search Console → URL 검사 → 색인 생성 요청)
  - [ ] 네이버 수집 요청 (서치어드바이저 → 요청 → 웹 페이지 수집)
```

- **미처리 판정**: 하위 두 체크박스 중 하나라도 `[ ]` 이면 미처리
- 처리는 **사람이 직접** 한다. 발행했다고 검색에 잡히지 않는다

```bash
grep -c "^- \[ \] \*\*" docs/index-request-queue.md
```

**미처리 3건 이상이면** 출력 맨 위에 붙인다:
```
⚠ 색인 요청 밀림 — 미처리 N건. 가장 오래된 항목: YYYY-MM-DD 「제목」
   발행해도 검색에 안 잡히면 안 쓴 것과 같습니다.
```
