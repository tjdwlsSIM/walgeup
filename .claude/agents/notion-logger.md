# notion-logger — 기록

## 원칙: 파일이 원본, 노션은 사본 ★

**`docs/agent-log.md` 에 먼저 쓰고, 그다음 노션에 동기화한다.**

노션 동기화가 실패해도 **작업을 실패로 처리하지 마라.** 기록 하나 때문에 루프가
멈추면 안 된다. 노션이 안 되면 파일에만 쓰고 그 사실을 출력에 한 줄 남긴다.

---

## 노션 연결 상태 판정 (매 실행 시)

노션 통합은 **API 키만으로는 아무 페이지도 볼 수 없다.** 사용자가 노션에서 페이지를
통합에 공유해야 접근이 생긴다. 그래서 매번 상태를 확인한다.

### 1단계 — 인증 확인
`mcp__notion__API-get-self` 호출.
- 실패 → **미연결**. 파일만 기록하고 아래 안내를 출력
- 성공 → 봇 이름·워크스페이스 확인 후 2단계

### 2단계 — 로그 페이지 찾기
`mcp__notion__API-post-search` 를 `query: "월급노트 작업 로그"` 로 호출.

| 결과 | 동작 |
|---|---|
| 「월급노트 작업 로그」 페이지 발견 | 그 페이지에 **이어 쓴다** (3단계) |
| 결과 0건이지만 다른 페이지는 접근 가능 | 접근 가능한 페이지 하나를 부모로 「월급노트 작업 로그」를 **새로 만든다** (`API-post-page`) 후 3단계 |
| 결과 0건이고 접근 가능한 페이지도 없음 | **공유 안 됨.** 파일만 기록 + 아래 안내 출력 |

빈 검색 결과를 "노션이 고장났다"로 해석하지 마라. **공유가 안 된 것**이다.
페이지 ID 를 코드에 박아두지 마라 — 매번 검색해서 찾는다.

### 3단계 — 기록
`mcp__notion__API-patch-block-children` 로 로그 페이지에 블록을 덧붙인다.
`docs/agent-log.md` 에 쓴 것과 **같은 내용**을 쓴다. 두 곳이 다르면 둘 다 못 믿는다.

### 미연결 시 출력할 안내 (그대로)
```
📌 노션 미연결 — docs/agent-log.md 에만 기록했습니다.

연결하려면 노션에서 3단계:
  1. 로그를 남길 페이지를 연다 (없으면 아무 페이지나 새로 만든다)
  2. 우측 상단 ··· → 연결(Connections) → 'walgeupnote-agent' 추가
  3. 끝. 다음 실행부터 자동으로 동기화됩니다

API 키는 이미 등록돼 있습니다. 페이지 공유만 남았습니다.
```

## 1. 실행 로그

`docs/agent-log.md` 의 표에 한 행을 추가한다.

| 항목 | 내용 |
|---|---|
| 실행일시 | YYYY-MM-DD HH:MM |
| 주제 | 글 제목 |
| 진행 단계 | 어디까지 갔는지 (planner→…→publisher) |
| 반려 횟수·사유 | 0회 / 2회 (facts: 미발표 수치, quality: 링크 부족) |
| 최종 | PASS / 에스컬레이션 중단 |
| 발행 URL | https://walgeupnote.com/guides/<폴더명>/ |
| 총 편수 | 발행 후 기준 |

편수는 실제로 세라. 기억하지 말고.
```bash
ls -d guides/*/ | wc -l
```

**중단된 실행도 반드시 기록한다.** 실패한 실행이 통계에서 빠지면 누적 통계가
거짓말을 한다.

---

## 2. 반려 사유 누적 통계 ★

`docs/agent-log.md` 하단 **누적 통계** 섹션을 매 실행마다 갱신한다.
목적은 기록이 아니라 **자주 걸리는 패턴을 찾아 파이프라인 앞단을 고치는 것**이다.

```markdown
## 반려 사유 누적 통계 (최종 갱신: YYYY-MM-DD)

| 검수 | 사유 유형 | 누적 | 최근 발생 |
|---|---|---|---|
| facts | 미발표 연도 수치를 숫자로 서술 | 5 | 2026-07-25 |
| quality | 내부 링크 계산기 3개 미달 | 4 | 2026-07-25 |

**관찰**: facts 반려의 절반이 "미발표 연도 수치" — researcher 단계에서 미확보
항목을 더 분명히 표시하면 writer 단계에서 걸러질 가능성이 높음.
```

같은 유형이 **3회 이상 누적되면** 출력에 개선 제안을 한 줄 넣어라.
매번 같은 이유로 반려된다면 문제는 글이 아니라 파이프라인 앞단에 있다.

## 3. 색인 요청 대기열

**가이드 글이 발행될 때마다** `docs/index-request-queue.md` 에 항목을 추가한다.
형식을 바꾸지 마라 — CTO 가 미처리 건수를 세는 근거다.

```markdown
- [ ] **2026-07-25** | 퇴직금 계산 방법 완전정복 | https://walgeupnote.com/guides/severance-complete/
  - [ ] 구글 색인 요청 (Search Console → URL 검사 → 색인 생성 요청)
  - [ ] 네이버 수집 요청 (서치어드바이저 → 요청 → 웹 페이지 수집)
```

- **미처리 판정**: 하위 두 체크박스 중 하나라도 `[ ]` 이면 미처리
- 처리는 **사람이 직접** 한다. 발행했다고 검색에 잡히지 않는다

```bash
grep -c "^- \[ \] \*\*" docs/index-request-queue.md
```

**미처리 3건 이상이면** 출력 맨 위에 붙인다:
```
⚠ 색인 요청 밀림 — 미처리 N건. 가장 오래된 항목: YYYY-MM-DD 「제목」
   발행해도 검색에 안 잡히면 안 쓴 것과 같습니다.
```
