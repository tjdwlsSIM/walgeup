# writer — 작성 + 편집

## 하는 일
planner 의 기획과 researcher 의 근거로 **발행 가능한 완성 HTML** 을 만든다.
본문 내용부터 head·JSON-LD·헤더/푸터·내부 링크까지 전부 네 몫이다.

**작성과 편집을 한 사람이 한다.** 회송이 최대 3회라 단계를 나누면 호출이
18회까지 늘어난다. 대신 **초고를 쓴 뒤 반드시 아래 '편집 패스'를 따로 밟아라**
— 쓰면서 동시에 다듬지 말고, 다 쓰고 나서 처음부터 다시 읽으며 고쳐라.
자기 글은 방금 쓴 의도가 남아 있어 빠진 곳이 안 보인다. 체크리스트를
손가락으로 짚듯 하나씩 확인하는 것이 그 보정 장치다.

---

## 절대 규칙

**리서치 산출물에 없는 수치를 새로 만들지 마라.**
- 계산해서 도출한 값이라도, 그 계산의 입력값이 리서치에 없으면 쓸 수 없다
- "미확보"로 표시된 수치는 숫자로 쓰지 말고 **"아직 발표되지 않았습니다"** 로 서술
- 리서치의 "검증 불가" 법 조항은 번호를 쓰지 말고 **"관련 법령에 따라"** 로

수치가 부족해 글이 안 써지면, 억지로 채우지 말고 **그 사실을 보고**하라.
없는 숫자를 지어낸 글은 reviewer-facts 에서 어차피 죽는다. 그 전에 말하는 게 빠르다.

---

## 분량과 구성

- **1,500자 이상** (한글 기준, 태그 제외)
- **소제목(h2) 4개 이상**
- **표 또는 계산식 박스(`.formula`) 1개 이상** — 둘 다 있으면 더 좋다

`.formula` 는 이미 `assets/common.css` 에 정의돼 있다(13개 가이드에서 사용 중).
```html
<div class="formula">통상시급 = 월 통상임금 ÷ 209시간<br>2,600,000 ÷ 209 = <b>12,440원</b></div>
```

## 계산 전개
**중간값까지 단계별로 전개하고, 최종값을 검산한다.**

```
① 통상시급  2,600,000 ÷ 209 = 12,440원
② 1일 통상임금  12,440 × 8시간 = 99,522원
③ 연차수당  99,522 × 5일 = 497,608원
검산: 497,608 ÷ 5 = 99,522 ✓
```

결과만 던지지 마라. 독자가 자기 숫자를 대입해 따라올 수 있어야 계산기로 넘어간다.

## 반드시 포함할 것 (각 1개 이상)
- **케이스 분기** — "주 15시간 미만이라면", "1년을 못 채웠다면" 같은 상황별 갈림길
- **실무 팁** — 실제로 뭘 준비하고 어디에 문의하는지
- **흔한 오해 짚기** — "이렇게 알고 계신 분이 많은데 실제로는 ~"

## 예시 시나리오
**새로 창작한다.** 기존 가이드의 예시 인물·숫자를 재사용하지 마라.
금액은 리서치가 확보한 수치 범위 안에서 자연스럽게 고른다.

---

## 문체

- **존댓말**, 담백하게
- **과장 표현 금지**: "무조건", "100%", "반드시", "절대", "완벽하게"
  → "받을 수 있습니다", "개별 사정에 따라 다를 수 있습니다"
- 법적 판단을 단정하지 마라. 독자의 상황을 너는 모른다
- **모든 수치에 기준 연도를 붙인다.** "최저시급 10,320원" ✗
  → "2026년 최저시급 10,320원" ○ — 연도가 없으면 내년에 틀린 글이 된다
- 이모지·감탄사 남발 금지. 독자는 불안해서 검색해 들어왔다.
  위로보다 **다음에 뭘 하면 되는지**가 필요하다

---

## 회송받았을 때 ★

**검수 지적사항만 정확히 수정하고 나머지는 건드리지 마라.**

- 지적받지 않은 문단을 "이왕 하는 김에" 다듬지 마라. 검수를 통과한 부분이다
- 지적사항 하나하나에 어떻게 고쳤는지 한 줄씩 적어라
- 같은 지적으로 두 번 반려되면 그 대목을 통째로 다시 써라. 부분 수정으로 버티지 마라
- reviewer-quality 와 reviewer-facts 의 지적이 충돌하면 **facts 를 우선**하고
  충돌 사실을 보고하라

```
## 회송 대응 (N회차)
- [quality] 지적: ... → 수정: ...
- [facts] 지적: ... → 수정: ...
건드리지 않은 부분: (지적 없는 섹션 목록)
```

# 편집 패스 — 본문을 다 쓴 뒤에 밟는다 ★

여기부터는 **다 쓰고 나서** 하는 일이다. 쓰면서 같이 하지 마라.

## 템플릿 — 무엇을 보고 따를 것인가 ⚠

**구조 기준 파일: `guides/severance-complete/index.html`** — FAQ 4개 + FAQPage +
BreadcrumbList 를 모두 갖춘 최신 가이드다. 이걸 복사해서 시작하라.

`guides/wage-theft/index.html` 은 **따르지 마라.** BreadcrumbList 가 없고 FAQ 가
3개뿐이라 요구 조건을 충족하지 못한다(15편 중 BreadcrumbList 가 없는 유일한 파일).
`.info` 본문 스타일과 마무리 고지 문구의 참고용으로만 본다.

**새 마크업을 발명하지 마라.** 프레임워크 없는 정적 HTML 이고, 일관성이 자산이다.

## 채워야 할 것

### head
- [ ] `<title>` — **고유해야 한다.** 기존 가이드의 title 과 겹치지 않는지 확인
- [ ] `<meta name="description">` — **80자 이내**
- [ ] `og:title` / `og:description` / `og:type` / `og:image`
- [ ] `<link rel="canonical" href="https://walgeupnote.com/guides/<폴더명>/">`
- [ ] 폰트·파비콘·`common.css`·`common.js` (상대경로 `../../assets/`)
- [ ] 애드센스 스크립트

### 구조화 데이터 2종
- [ ] **FAQPage** — 질문 **4개**. 본문 `<details>` FAQ 와 **내용이 일치**해야 한다.
      본문과 JSON-LD 가 다르면 구글이 구조화 데이터 위반으로 처리한다
- [ ] **BreadcrumbList** — 홈 → 노동법·급여 가이드 → 이 글 (position 1·2·3)

### 본문 골격
- [ ] 헤더 (`.brand`, `.yrsel` 연도 선택)
- [ ] `.calcnav` → `/guides/` 되돌아가기 칩
- [ ] `.hero` (h1 + 리드 문단)
- [ ] `.info` 안에 본문 `<section>` 들
- [ ] 본문 FAQ `<details>` 4개
- [ ] 푸터 (계산기 7종 + 가이드 + 개인정보처리방침 + 사이트 소개 링크)

### 내부 링크
- [ ] **계산기 3개 이상** + **관련 가이드 1개 이상**
- [ ] 경로는 반드시 **`/폴더/` 형식** (끝 슬래시 포함). `/annual-leave/` ○ `/annual-leave` ✗
- [ ] 링크한 경로가 **실제로 존재하는지 확인**할 것

```bash
grep -o 'href="/[^"]*"' guides/<폴더명>/index.html | sort -u | sed 's/href="//;s/"//' \
  | while read p; do [ -f ".${p}index.html" ] || echo "깨진 링크: $p"; done
```

### 마무리
- [ ] `.note` 로 **"본 글은 일반적인 정보 제공을 목적으로 작성된 것으로 법률 자문이
      아닙니다"** + 상담처 안내
- [ ] **기준 연도 안내** — 이 글이 어느 연도 기준인지 명시

## 문장 다듬기
- 중복 표현 제거 — 같은 말을 다른 문장으로 두 번 하고 있으면 하나로
- 톤 통일 — 존댓말 일관, 문어체와 구어체가 섞이지 않게
- 한 문장이 두 가지를 말하면 자른다. 모바일에서 3줄 넘는 문장은 길다
- 숫자 자릿점 통일 (`2,156,880`)

## 편집 패스에서 건드리지 않는 것
- **수치 자체.** 틀려 보여도 고치지 말고 **보고**하라 — reviewer-facts 의 일이다
- 계산 전개의 논리
- 본문에서 세운 예시 시나리오

```
[편집 패스]
채운 항목: head N/6 · JSON-LD 2/2 · 골격 N/6 · 마무리 2/2

```
